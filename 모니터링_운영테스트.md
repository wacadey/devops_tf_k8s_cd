# CD + 모니터링(추가) 추가 상세 내용
- argocd/monitoring-application.yaml.tpl
  - ArgoCD가 monitoring 디렉터리를 감시하고 Prometheus/Grafana를 자동 배포하도록 정의하는 Application 템플릿

- monitoring/
  - kube-prometheus-stack-values.yaml
    - kube-prometheus-stack Helm Chart의 설치 옵션을 정의하는 설정 파일
    - Prometheus, Grafana, Alertmanager, 저장 용량, 리소스 제한 등을 설정
  - resources/
    - kustomization.yaml
      - monitoring/resources 아래의 추가 Kubernetes 리소스를 한 번에 묶어 배포하는 Kustomize 설정 파일
    - grafana-dashboard-autoscaling.yaml
      - Pod 수, CPU 사용률, HPA 상태, Node 상태를 확인하는 Grafana 대시보드를 등록하는 ConfigMap
    - prometheus-rules.yaml
      - Pod 장애, CPU 과부하, HPA 최대치 도달 등의 상황을 감지하는 Prometheus 경고 규칙
    - servicemonitor-was.yaml
      - Prometheus가 WAS Service의 /metrics 주소를 자동으로 수집하도록 연결하는 ServiceMonitor

- load-test/
  - hpa-test.js
    - 트래픽을 단계적으로 증가시켜 WAS Pod가 HPA에 의해 확장되는지 확인하는 k6 부하 테스트 스크립트
  - smoke-test.js
    - 애플리케이션 주소가 정상 응답하는지 짧고 가볍게 확인하는 k6 기본 접속 테스트
  - run-load-test.sh
    - macOS/Linux에서 hpa-test.js를 실행하는 부하 테스트 실행 스크립트
  - run-load-test.bat
    - Windows CMD에서 hpa-test.js를 실행하는 부하 테스트 실행 배치 파일
  - run-smoke-test.sh
    - macOS/Linux에서 smoke-test.js를 실행하는 기본 접속 확인 스크립트
  - run-smoke-test.bat
    - Windows CMD에서 smoke-test.js를 실행하는 기본 접속 확인 배치 파일

- scripts/
  - setup-monitoring.sh
    - macOS/Linux에서 Helm Repository 등록과 ArgoCD 모니터링 Application 생성을 자동으로 수행하는 설치 스크립트
  - setup-monitoring.bat
    - Windows에서 Helm Repository 등록과 ArgoCD 모니터링 Application 생성을 자동으로 수행하는 설치 배치 파일
  - grafana-port-forward.sh
    - macOS/Linux에서 Grafana Service를 localhost:3000으로 연결하는 포트 포워딩 스크립트
  - grafana-port-forward.bat
    - Windows에서 Grafana Service를 localhost:3000으로 연결하는 포트 포워딩 배치 파일
  - get-grafana-password.sh
    - macOS/Linux에서 Kubernetes Secret에 저장된 Grafana 관리자 비밀번호를 조회하는 스크립트
  - get-grafana-password.bat
    - Windows에서 Kubernetes Secret에 저장된 Grafana 관리자 비밀번호를 조회하는 배치 파일
  - watch-autoscaling.sh
    - macOS/Linux에서 HPA, Pod, CPU 사용량, Node 변화를 반복 조회하는 모니터링 스크립트
  - watch-autoscaling.ps1
    - Windows PowerShell에서 HPA, Pod, CPU 사용량, Node 변화를 반복 조회하는 모니터링 스크립트

- README-MONITORING.md
    - 모니터링 설치, Grafana 접속, 부하 테스트 실행, Pod 확장 확인 순서를 정리한 실습 안내 문서

- .gitignore.addition
  - Helm 임시 파일, 로컬 설정 파일, 테스트 결과 등 Git에 올리지 않을 항목을 기존 .gitignore에 추가하기 위한 내용

          │

          ▼
  WEB Deployment

          ▼
  WAS Deployment
          │
          ├───────────────┐
          │               │
          ▼               ▼
        RDS           Metrics Server
                          │
                          ▼
                  HPA가 CPU/메모리 확인
                          │
                          ▼
                  Pod 개수 자동 조절
                          │
                  Node 용량이 부족하면
                          ▼
                EKS Auto Mode Node 확장


  각 Node / Pod / Deployment
          │
          ▼
  Prometheus
    ├─ kube-state-metrics
    ├─ node-exporter
    ├─ Kubernetes API
    └─ 애플리케이션 metrics
          │
          ▼
  Grafana Dashboard
  ```

# 역활

| 구성요소           | 역할                               |
| -------------- | -------------------------------- |
| Metrics Server | HPA가 CPU·메모리를 보고 Pod 수를 조절하도록 지원 |
| Prometheus     | `장기간` 메트릭 수집·저장·조회                 |
| Grafana        | Prometheus 데이터를 `대시보드로 시각화`        |
| HPA            | Pod 수를 자동으로 증가·감소                |
| EKS Auto Mode  | Pod를 배치할 Node가 부족하면 Node까지 자동 증가 |
| k6             | 실제 HTTP 트래픽 발생                   |

## 2단계. Prometheus와 Grafana 설치
- Helm :Kubernetes 패키지 관리자
  - 여러 개의 Kubernetes YAML 파일을 하나의 설치 패키지로 묶어, 간단한 명령어로 설치·수정·삭제할 수 있게 해주는 도구
  - 파이썬 pip, 노드의 npm
  
  - 설치
    - 윈도우
      - winget install Helm.Helm
    - 맥
      - brew install helm
    - 확인
      - helm version

  - 절차
    ```
      # Helm Repository 등록
      helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
      helm repo update
    ```
  - Prometheus와 Grafana를 직접 설치
    - 여러개의 YAML 생성 필요 -> 번잡 -> 시간/절차 과하게 소요
    - 헬름으로 설치 (심플)

  - 헬름 구성요소
    - Chart: Kubernetes 리소스 YAML을 묶어놓은 설치 패키지
    - values.yaml: 사용자가 변경할 설정값
    - Release: Chart등 실제 클러스터에 설치한 결과
    - Repository: Chart등 보관하는 저장소

  - 작업
      # monitoring Namespace 생성
      kubectl create namespace monitoring
      --- 
      이미 있다면 : AlreadyExists

      # 프로메테우스/그라파나 설치
      helm upgrade --install kube-prometheus-stack prometheus-community/kube-prometheus-stack -n monitoring -f monitoring/kube-prometheus-stack-values.yaml

      # 설치 확인
      kubectl get pods -n monitoring
      ---
      alertmanager-...
      grafana-......

      # ServiceMonitor 적용
      kubectl apply -k monitoring/resources
      # 확인
      kubectl get servicemonitor -n monitoring

      de-ai-12-was


    ```

  核心目标是验证整套链路：

  k6 制造访问压力
  → ALB → WEB → WAS
  → CPU/内存升高
  → HPA 自动增加 Pod
  → 节点容量不足时 EKS Auto Mode 增加 Node
  → Prometheus 收集指标
  → Grafana 展示监控结果

  它主要包含以下内容：

  1. 检查当前 Kubernetes 环境
      - Node、Pod、Deployment、Service、Ingress 状态
      - CPU、内存使用情况
      - WEB/WAS 的 HPA 配置
      - 当前配置为最少 2 个、最多 4 个 Pod，CPU 目标值为 60%

  2. 安装监控组件
      - 使用 Helm 安装 kube-prometheus-stack
      - 其中包含 Prometheus、Grafana、Alertmanager 等
      - 应用自定义的 ServiceMonitor、告警规则和 Grafana Dashboard

  3. 配置 WAS 指标采集
      - 通过 monitoring: enabled 标签，让 ServiceMonitor 找到真正的 WAS Service
      - Prometheus 再从 WAS 的 /metrics 地址采集应用指标

  4. 访问和检查 Grafana/Prometheus
      - Prometheus：localhost:9090
      - Grafana：localhost:3000
      - 检查 Prometheus Target 是否为 UP
      - 查看 Cluster、Namespace、Pod、Workload 和 HPA 等 Dashboard

  5. 执行压力测试
      - smoke-test：短时间、轻量测试，用于确认应用能否正常响应
      - hpa-test：逐步增加流量，用于触发 HPA 扩容
      - 使用 k6 向 ALB/API 地址持续发送请求

  6. 观察自动扩缩容
      - 同时监控 HPA 和 Pod 数量
      - 验证压力升高后 Pod 是否从 2 个增加到最多 4 个
      - 压力结束后，等待 HPA 的 300 秒缩容稳定窗口，再观察 Pod 是否减少

  简单来说，这个文件不是程序代码，而是一个已经记录了部分实际执行结果的 监控部署 + 压力
  测试 + HPA 扩缩容验证教程。最终要证明的是：应用有压力时能够自动扩容，而且整个变化过程
  能在 Prometheus 和 Grafana 中被观察到。
